# Make a video from your narration

This guide takes you from a voice recording to a finished MP4 with a hand-drawn cartoon look. You don't need to write code. You do need to follow the steps in order.

## Set up your computer once

- **Node.js.** It runs the toolkit. The project doesn't pin a version; it was tested with Node 24.
- **FFmpeg**, with both `ffmpeg` and `ffprobe` on your PATH. The toolkit uses `ffprobe` to measure your narration. Without it, compiling stops with the message `ffprobe is not installed or not on PATH`, which says to install FFmpeg.
- **Google Chrome** or Chromium. Rendering uses it. Run `npx hyperframes doctor` to check everything. The first run downloads the HyperFrames renderer, so it needs internet access.

## What you need

- **Your narration.** A recording of you reading the script, saved as `narration.mp3` or `narration.wav`. Its length sets the length of the video.
- **Your transcript.** A text file with one line per caption, each starting with its time in square brackets, like `[0:04] Welcome back to the channel.`. It doesn't have to be perfect; the toolkit fixes spelling mistakes.
- **Your script.** The clean text of what you read, saved as `script.txt`. The toolkit uses it to correct the spelling in the transcript.
- **A scene sheet.** A plan that splits the video into scenes. Each scene has a background, the characters and objects in it, what happens and when, any on-screen headline, and how it ends. You can make it by pasting your timed script into your coding assistant and following the rules in [docs/scene-sheet-spec.md](scene-sheet-spec.md). Save the result as `scene_sheet.md`.

## Steps

1. **Make a project folder.** Inside the project, create `projects/<your-video-name>/`. Put the files in it like this:

   ```
   projects/<your-video-name>/
     audio/narration.mp3
     transcript.txt
     script.txt
     scene_sheet.md
   ```

2. **Open the control panel.** Run `npm run ui`, then open `http://127.0.0.1:4321` in your browser. Your new project should appear in the project list.

3. **Compile.** Click **Compile**. The toolkit reads your four files and writes:
   - `captions.srt`, your corrected subtitles.
   - A build report, showing every subtitle fix and any warnings.
   - A build plan for the animation.

   Fix every error it reports. Warnings don't stop the build, but read them. A warning usually means a scene is holding still for too long.

4. **Draw the scenes.** Ask your coding assistant to build the film from the build plan. It follows the skill steps in `skills/doodle-*/`, in order. Build the first three scenes, check them, and then continue in batches of five.

5. **Check the film.** Click **Film gate**, then **Lint** and **Check**. Fix anything they flag.

6. **Render.** Click **Render MP4**. The video is saved as `projects/<your-video-name>/out/<your-video-name>.mp4`. It's 1920×1080, 24 frames per second, and the same length as your narration.

7. **Review.** Watch the whole video. Check the subtitles against the narration. Make changes to the scene sheet and repeat from step 3 if needed.

## Long films (up to 10 minutes)

- **Length.** The video is as long as your narration, so a 10-minute narration gives a 10-minute film. The generator needs the same number of scenes as your scene sheet; a scene sheet of 60 ten-second scenes is the tested case.
- **One cast, many scenes.** Every scene uses the same characters, drawn from one shared set of shapes, so a character looks the same from the first scene to the last. Props and layouts are placed per scene from the scene sheet.
- **Frame counts.** Scenes start and end on whole frames at 24 fps. The scene frames always add up to the total frame count of the narration.
- **Build and render speed.** On the test machine, a 10-minute, 60-scene film builds in under a second. The render took about 20 minutes (19 min of capture) and produced a 1920×1080, 24 fps MP4 of 14,400 frames. Rendering runs in the background, so the control panel's render step can take a while.
- **Long captions.** Captions are split into one file per minute, `film/compositions/captions-01.html`, `captions-02.html` and so on. Each file holds only the captions that fall in its minute, so lint has no large file to warn about.

## Good to know

- **Nothing is generated by AI video tools.** The pictures are drawn as code, so the style is consistent and repeatable.
- **Hard cuts by default.** Scenes change with a straight cut unless the scene sheet asks for a fade.
- **The toolkit runs on your computer.** Compiling, checking and rendering all happen locally.
- **If something stops the build,** it usually means a file is missing, a timestamp is wrong, or the scene sheet doesn't follow the format. The compile report says which one.
